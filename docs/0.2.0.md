# THC 0.2.0: build spec

**Status:** ready to build. Current version: 0.1.3. This is a minor release (big new features): a real queue, music search, listening history, a privacy inspection tool, media keys, and an always-on-top option.

## How to work on this (read first)
- Work on `dev`; never push to `main`. Commit and push after each slice (see "Build order").
- **Deliver 0.2.0 efficiently.** Build what this file says.
- **If you find a bug, a missing piece, an idea, or anything out of scope: file a new GitHub issue and move on.** Do not stop to fix it, and do not widen the scope of a slice. Only fix it now if it blocks the slice you are on, and say so in the commit.
- Keep `README.md`, `CHANGELOG.md` and this file true as you go. If you deviate from this spec, write the deviation here and say why.
- The hard rules in `AGENTS.md` still apply (no network, never write to media files, C only, three operating systems).

## Rules for every feature
- Private and local: no network calls, no telemetry, no accounts.
- Never write to, move, or rename media files.
- Works on Windows, Linux (Wayland and X11) and macOS.
- Keyboard accessible, scalable text, high contrast, readable without relying on color.
- Every setting lives in `settings.ini` and has a control in Settings; every key action is a remappable hotkey.
- Logic that does not need SDL goes in `thc_core` (testable); tests land with the code.
- Confirmation windows (queue clear, history clear) are real modal dialogs, not "press twice".

## 1. Data foundation (history schema v2, settings)

**Today:** `history.db` has one `history` table keyed by relative path + size, schema version 1, with a migration mechanism (`history_open_ex`, `PRAGMA user_version`, backup before upgrade). `settings.h` has a single `remember_history`.

**Database changes (schema version 2: one numbered migration in `src/history.c`, backup kept as `history.db.v1.bak`).** Follow the "History compatibility" rule in `AGENTS.md`: new columns must be nullable or have a `DEFAULT`; only add columns, tables and indexes; bump `HISTORY_SCHEMA_VERSION`; extend `tests/test_history_compat.c`; never reset `user_version` or delete a database.
- `history` gets `kind` (0 video, 1 music, 2 audiobook; `DEFAULT 0`) and `last_played` (unix time; `DEFAULT 0`).
- New table `plays`: `id`, `rel_path`, `size`, `kind`, `played_at`, `listened_seconds`. One row each time an item counts as played.
- New table `queue_backlog`: `queue` (0 music/audio, 1 video), `ord`, `rel_path`, `size`, `kind`, `title`, `played_at`. Used only when "Keep queue backlog between sessions" is on.
- History is **kept forever**: no expiry or pruning.

**Settings** (`settings.ini`, Settings page noted):

| Key | Type | Default | Where |
| --- | --- | --- | --- |
| `history_video` | bool | true | Privacy |
| `history_music` | bool | true | Privacy |
| `history_books` | bool | true | Privacy |
| `play_threshold_music` | percent 50–100 | 65 | Playback |
| `music_resume_min_minutes` | int 0–60 | 10 | Playback |
| `private_session` | bool, not saved | false | Privacy |

- The old `remember_history` migrates into all three `history_*` keys, then is dropped.
- When history is off for a portal: nothing new is recorded for it (no positions, plays or backlog), so resume does not work there. Existing data stays until the user clears it. The setting's text says so.

**Files:** `include/history.h`, `src/history.c`, `include/settings.h`, `src/settings.c`, `src/screen_settings.c`.

**Done when:** a v1 database upgrades to v2 with all rows intact and a `.bak` copy; a v2 file opened by an older THC still works (existing compat tests extended); `remember_history` migrates correctly; settings round-trip.

## 2. Queue (#1)

### Behavior
- **Two queues**, separate but interchangeable: the **music queue** (songs and audiobooks) and the **video queue**. A queue is an ordered list of items of **any** type; each type has a **home queue** (video → video queue; song and audiobook → music queue).
- **Adding:** "Add" puts items at the **end** by default. A second action, "Add to the other queue", sends an item to the other queue. Items can be moved between queues in the panel.
- **Adding groups:** a show or season adds its episodes in order (show → season → episode); an album adds its tracks in order (by disc and track number). For shows, "Add unwatched only" is offered.
- **Right-click menu** on any item (card, row, track, episode): Play now, Play next, Add to end, Add to the other queue, Play from here, Add unwatched only (shows), Remove (in the queue), Move to the other queue, Go to album or show, Mark played or unplayed.
- **Only one queue is active** at a time. Starting playback in a queue makes it active.
- **Backlog:** played items stay in the queue above the current one (greyed), like most music players. **Previous** walks back through them. The backlog **resets when THC closes**, unless "Keep queue backlog between sessions" is on (then only the backlog is saved, in `queue_backlog`, and restored next start; the upcoming queue always starts empty). It follows the history switches: if history is off for a portal, that portal's items are not saved in the backlog.
- **Order:** reorder (drag, and keyboard Alt+Up/Down), remove, clear (**confirmation window**), skip next/previous. **Shuffle** only reorders what is still to play and keeps the current item. **Repeat:** off / one / all.
- **Previous button:** restarts the current item if more than 3 seconds in, otherwise goes back (setting to always go back).
- **Auto-advance** on finish; the finished item is recorded in history first. Optional "next episode in 5 s" countdown for video (off by default).
- **Session only** (the upcoming queue is never saved).

### Playing items (the dispatcher)
One player chooses a backend per item when it comes up:

| Item | Backend | Notes |
| --- | --- | --- |
| Video | The **single MPV window** for the whole video queue | The next video loads into the same window (no flicker) |
| Song | THC's own engine (`audio.c`), no MPV window | |
| Audiobook MP3 | THC's own engine | audiobook speed and skip settings apply |
| Audiobook M4B | libmpv with no window (inside THC's player bar) | needs libmpv, as today |

- **A video in the music queue** opens in a **new MPV window** (default). Per-item overrides: **listen only** (sound, no window) or **skip**.
- **A song or audiobook in the video queue** plays in THC's player bar; the MPV window closes, and reopens for the next video.
- **Starting a video pauses music** (setting; on by default). A second setting resumes the music after the video ends.
- **Queue chaining:** per queue, "after this queue ends, play: nothing / the other queue". Without a chain, playback **stops** at the end. A chain runs **once per start**: two queues chained to each other must not loop forever.
- **Resume positions** for queued items come from history (per type: videos and audiobooks resume, songs start at 0 by default).
- Items played from the queue are recorded in history like any other play (section 3).

### Export and import
- Optional, user-initiated: export the current queue to a file the user chooses; import to rebuild one.
- Format: **M3U8** (UTF-8) plus a `#THC-QUEUE:music` / `#THC-QUEUE:video` header line and per-item `#THC-KIND:` comments. Paths are relative to the library folder where possible (setting: relative or absolute).
- Import skips missing files and lists them. Order and the home queue are preserved.
- Export never writes into media folders unless the user picks one.

### Settings

| Key | Type | Default |
| --- | --- | --- |
| `queue_auto_advance_video` | bool | true |
| `queue_next_countdown` | bool | false |
| `queue_repeat` | off/one/all | off |
| `queue_shuffle` | bool | false |
| `queue_prev_restarts` | bool | true |
| `queue_add_position` | end/next | end |
| `queue_add_target` | home/active | home |
| `queue_resume_video` / `_song` / `_book` | bool | true / false / true |
| `queue_season_unwatched_only` | bool | false |
| `queue_keep_backlog` | bool | false |
| `queue_chain_music` / `queue_chain_video` | none/other | none |
| `queue_video_in_music` | window/listen/skip | window |
| `queue_pause_music_on_video` | bool | true |
| `queue_resume_music_after_video` | bool | true |
| `queue_export_relative` | bool | true |
| hotkeys | queue panel, add, play next, reorder up/down, remove | remappable |

### Data model
- `QueueItem`: kind, root, relative path, full path, size, title, subtitle, art key, home queue, play mode (window/listen/skip), played flag.
- `Queue`: items, current index, shuffle order, repeat, chain target. `thc_core` owns the logic (add, insert, move, remove, next/previous with backlog, shuffle, repeat, chain, M3U8 read/write); the app layer owns the backends.
- Limit: at least 5,000 items per queue (today's audio list is 512).

### Files
New: `include/queue.h`, `src/queue.c` (core), `src/player.c` (dispatcher), `src/screen_queue.c` (panel), a context-menu widget and modal confirm dialog in `src/ui.c`. Changed: `src/music.c` (audio list becomes a backend), `src/video.c` and `src/main.c` (`app_play_video`, `pump_video`), `src/portal_video.c`, `src/portal_music.c`, `src/portal_books.c`, `src/settings.c`, `src/screen_settings.c`, `CMakeLists.txt`.

### Acceptance tests
- Core (no SDL): add/insert/move/remove; next/previous with backlog; shuffle keeps the current item and only shuffles the rest; repeat modes; chaining runs once and cannot loop; M3U8 round trip (relative and absolute paths, missing files, unicode); "add season" order; cross-queue move.
- Dispatcher with fake backends: the right backend per item; a video in the music queue opens a window; a song in the video queue closes it; pause/resume music around a video; stops at the end without a chain.
- History: items played from the queue record; backlog saved only when the setting is on and the portal's history is on.
- UI smoke (headless screenshot): panel, right-click menu, clear confirmation.
- No media file is modified.

## 3. Listening history (#11)

### Behavior
- A **play** counts when the listener reaches **65%** of a track (setting `play_threshold_music`). Each counted play adds a row to `plays` and bumps `play_count`/`last_played`.
- **Resume:** audiobooks and long audio resume; songs shorter than `music_resume_min_minutes` start at 0.
- **Views** in the music portal: **Recently played** (tracks, albums, audiobooks), **Continue listening** (in-progress audiobooks and long items), **Most played**; album pages show "X of Y tracks played".
- **Controls:** mark played/unplayed; remove one item from history; **clear** history (per portal, behind a **confirmation window**); **turn off saving new history per portal** (Video, Music, Audiobooks individually); **private session** (nothing recorded until THC restarts); **export** history as JSON or CSV (user chooses where).
- History is kept forever.

### Files
`include/history.h`, `src/history.c` (play events, recent, most played, clear by kind, remove, export), `src/music.c`/`src/player.c` (record plays), `src/portal_music.c`, `src/portal_books.c`, `src/screen_settings.c`.

### Acceptance tests
Play counted at 65% and not below; configurable threshold; per-portal off records nothing for that portal and still records the others; private session; clear by portal with data kept for the others; remove one item; export JSON/CSV content; queue plays recorded; v1→v2 migration keeps old positions.

## 4. Music search (#7)

### Behavior
- A search field at the top of the music portal (hotkey to focus, default `/`; clear button).
- **Search as you type**, with a short delay. Results grouped as **Artists / Albums / Songs**, with cover art.
- **What to search:** a picker with **All, Artists, Albums, Songs**. The default is **All, every time**. A setting "Remember my search scope" (off by default) keeps the last choice.
- **Light typo tolerance is always on** (no toggle): one edit allowed for words of 4 or more letters.
- Case, accent and punctuation insensitive ("beyonce" finds "Beyoncé").
- Ranking: exact, then prefix, then word start, then substring, then typo matches.
- **Audiobooks are never included** in music search, and there is no option for it.
- Selecting a result opens the artist or album page, or plays the song; results also have the right-click menu from the queue.
- Local only; reads the tag cache and folder tree; the index rebuilds when a scan or tag read finishes.

| Key | Type | Default |
| --- | --- | --- |
| `search_remember_scope` | bool | false |
| `search_last_scope` | enum | all |
| `search_results_per_group` | int 3–20 | 5 |
| `search_clear_on_leave` | bool | true |
| hotkey `search` | key | `/` |

### Files
New: `include/search.h`, `src/search.c` (core: normalization, index, matching, ranking, typo distance). Changed: `src/portal_music.c`, `src/tagcache.c` (index hook), `src/screen_settings.c`, `src/settings.c`.

### Acceptance tests
Accent/case/punctuation folding; ranking order; typo tolerance (one edit, not for short words); scope filtering; audiobook tracks never appear; unicode names; 50,000 tracks stay responsive (per-keystroke time recorded); index rebuild on rescan.

## 5. Media keys and now playing (new issue)

### Behavior
- Hardware **media keys** (play/pause, next, previous, stop, fast-forward, rewind) and the system "**now playing**" controls drive whichever queue is **active**.
- **Platforms:** Linux: MPRIS over the local D-Bus (load `libdbus-1` at run time, like libmpv, so it is not a hard dependency). Windows: System Media Transport Controls (media-key handling as fallback). macOS: Now Playing center and remote commands (a small Objective-C file).
- THC **claims the keys only while it has something loaded**, so other players keep them otherwise.
- **Previous** restarts after 3 s, as in the queue. **Stop pauses** and never clears the queue. Seek keys: 10 s for music and video, the audiobook skip length (30 s) for audiobooks.
- **What the system sees (privacy):** music and audiobooks share title, artist, album and cover; **video shares nothing** (the system just sees "THC"), so what you watch is not shown on lock screens or overlays. Each can be changed per portal.

| Key | Type | Default |
| --- | --- | --- |
| `mediakeys_mode` | off/focused/global | global |
| `nowplaying_music` / `_books` / `_video` | bool | true / true / false |
| `nowplaying_titles` | full/playing-only | full |
| `nowplaying_art` | bool | true |
| `mediakeys_seek_seconds` | int | 10 |

### Files
New: `include/mediakeys.h` (init, set metadata, set state, callbacks), `src/mediakeys_linux.c`, `src/mediakeys_win.c`, `src/mediakeys_mac.m`, a no-op fallback. Changed: `src/player.c`, `src/screen_settings.c`, `src/settings.c`, `CMakeLists.txt` (Objective-C on macOS).

### Acceptance tests
Fake platform backend: metadata is withheld for video by default; keys map to queue actions; keys are released when nothing is loaded; settings round-trip. Manual checklist per OS (media key, lock screen/notification, headphone button). Document what could not be tested.

## 6. Always-on-top (#18)

- **Step 1: feasibility.** Test `ontop` on Windows, macOS, X11 (a few window managers) and Wayland (GNOME, KDE, Sway). Record results in the issue.
- **Setting:** keep THC's MPV video window on top: **Off / While playing / Always**. THC sets MPV's `ontop` after startup (as a property, since `mpv.conf` overrides options set before startup); on macOS also `ontop-level` (window or system). "Ignore in fullscreen" (default on). A hotkey toggles it.
- **Wayland:** the setting shows a note ("Your compositor decides this") instead of pretending to work; THC gives its MPV window its own app id (`thc`) so users can write a compositor rule for it. If the test shows it cannot work somewhere, ship it only where it works.
- This setting is authoritative: `ontop` in `mpv.conf` is ignored, and the existing MPV config check marks it as controlled by THC.

| Key | Type | Default |
| --- | --- | --- |
| `video_ontop` | off/playing/always | off |
| `video_ontop_macos_level` | window/system | window |
| `video_ontop_ignore_fullscreen` | bool | true |

**Files:** `src/video.c`, `src/screen_settings.c`, `src/settings.c`, `src/mpvconf.c` (mark `ontop` as THC-controlled).
**Tests:** option values passed to MPV per mode; fullscreen handling; Wayland detection shows the note; settings round-trip.

## 7. `thc-inspect` (#14)

A **separate, small program** (not part of THC) that anyone can run beside THC to check what it really does. **Read-only. It never connects to the network itself.** Built from `tools/inspect/`, linking only SQLite and the C library.

### What it reports
1. **Files:** everything THC has written (settings, history database, thumbnails, tag/cache, MPV config) with sizes and dates.
2. **History database:** schema version and row counts per table; titles only when asked (`--show-titles`).
3. **Network connections:** for a running THC process, its open sockets, per OS (`/proc` on Linux, `libproc` on macOS, the extended TCP/UDP tables on Windows). Expected: none. Local D-Bus (media keys) is shown as local IPC, not network.
4. **Program contents:** whether the THC executable imports networking functions (ELF/PE/Mach-O import tables), against an allowed list; libmpv, which is loaded at run time, is reported separately with its own network capabilities.
5. **MPV config:** whether `mpv.conf` or scripts enable online features (`ytdl`, network protocols); whether THC's "block network in MPV" is on.
6. **Media untouched:** with `--media <folder>`, a before/after check mode that fingerprints files so a user can run THC, then confirm nothing changed.

### Options
| Flag | Meaning |
| --- | --- |
| `--data <dir>` | inspect any THC data folder (default: the standard one) |
| `--json` | machine-readable output (default is readable text) |
| `-v` / `-vv` | verbosity |
| `--show-titles` | include titles from history |
| `--pid <n>` | which running THC to check for connections |
| `--media <dir>` | media fingerprint mode |
| exit code | 0 pass, 1 findings, 2 error (so CI can use it) |

### Shipping
Built by CI for each OS and shipped **in the THC packages and as its own download**: `thc-inspect.exe` (Windows), a macOS binary, and `thc-inspect-<version>-x86_64.AppImage` (Linux). Version-stamped like THC.

### Settings integration
THC's **Block network in MPV** switch (default on: `ytdl=no`, no URL playlists, network protocols off for THC's MPV) and a small in-app "what THC stores" list in Settings → Privacy (data folder, files, sizes, open-folder button). *(Assumed to stay alongside `thc-inspect`; confirm.)*

| Key | Type | Default |
| --- | --- | --- |
| `mpv_block_network` | bool | true |

### Tests
Run `thc-inspect` against a fixture data folder (expected report, text and JSON); exit codes; a Linux test that runs THC's core under no network (`unshare -n`) and confirms it works; the imports check fails on a deliberately bad binary fixture; media fingerprint detects a changed file.
