# 0.2.0: release plan

**Status:** proposed. Current version is 0.1.3. Per the versioning rules, a minor release holds big new features: the queue (#1) is the headline, with the smaller music and privacy items alongside it.

## Goal
Add a real queue for audio and video, make music easier to find and keep track of, and give users a way to check that THC really is private and offline.

## Planned
- [ ] **#1 Comprehensive queue (headline).** THC-managed queue; separate music/audiobook and video queues by default, with an optional mixed order; session only; optional export and import as M3U8; reorder, skip, shuffle and repeat; keyboard accessible. See the issue and its export comment for the full spec.
- [ ] **#7 Search in the music portal.** Artists, albums and songs, search as you type, local only. Uses the audio tags from 0.1.1.
- [ ] **#11 Listening history.** Played items from the queue are recorded. A "Recently played" and "Continue listening" view, play counts, last played, mark played or unplayed, and a way to pause history. Audio positions already save; this adds the visible part.
- [ ] **#14 End-user trust check.** A way for users to verify THC makes no network calls and writes nothing into their media. Doubles as the "no network" test from #2.
- [ ] **#18 Always-on-top for MPV.** Start with a feasibility test on Windows, macOS, X11 and Wayland. Ship the setting only where it works, with a clear note where it doesn't.

## Housekeeping
- [ ] Verify and close **#8** (audio tags) and **#9** (video thumbnails), shipped in 0.1.1 (in progress by another agent).
- [ ] Update `CHANGELOG.md`, bump the version to 0.2.0 in `CMakeLists.txt`, and refresh the README.

## Not in 0.2.0
- **#15 Embedded MPV and pop-out settings** (easier after the queue lands), **#3 MPV config editor**, **#13 NSFW tagging**, **#19 Windows, macOS and BSD packages**, **#6 GLSL accessibility**, **#12 performance test plan**: later.

## Rules for every item
- Private and local: no network calls, no telemetry, no accounts.
- Never write to, move, or rename media files.
- Works on Windows, Linux (Wayland and X11) and macOS.
- Keyboard accessible, with scalable text and high contrast.
- Tests with each change; CI stays green on all three OSes.

## Done means
- Every planned item is shipped, or explicitly moved to a later release in this file.
- `ctest` and CI pass on all three OSes.
- Packages are rebuilt as 0.2.0 and the changelog lists each change with its issue number.

## Order of work
1. #1 queue (the others build on it).
2. #7 search and #11 listening history.
3. #14 trust check.
4. #18 feasibility, then ship only where it works.

## Open questions
- Is #18 worth shipping if it only works on three of four platforms?
- Should the trust check (#14) be a settings page, a command-line mode, or both?
