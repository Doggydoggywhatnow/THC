# 0.2.0: release plan

**Status:** proposed. Current version is 0.1.3. Per the versioning rules, a minor release holds big new features: the queue (#1) is the headline, with the smaller music and privacy items alongside it.

## Goal
Add a real queue for audio and video, make music easier to find and keep track of, and give users a way to check that THC really is private and offline.

## Planned
- [ ] **#1 Comprehensive queue (headline).** THC-managed queue; two queues (music and audiobooks, and video) that are separate but interchangeable: any item can go in either queue, and the player picks the right backend per item. Videos play in one MPV window; songs and audiobooks stay inside THC's own player. Session only; optional export and import as M3U8; reorder, skip, shuffle and repeat; keyboard accessible. See the issue and its export comment for the full spec.
- [ ] **#7 Search in the music portal.** Search as you type, local only, using the audio tags from 0.1.1. The user chooses what to search (all, artists, albums or songs). Light typo tolerance is always on, with no toggle. **Audiobooks are never part of music search** and there is no option to add them.
- [ ] **#11 Listening history.** Stored in the history database (a play event per listen). A play counts at **65%** of a track by default, changeable in Settings. History saving can be turned off **separately for each portal** (Video, Music, Audiobooks). Played items from the queue are recorded. A "Recently played" and "Continue listening" view, play counts, last played, mark played or unplayed, and a way to pause history. Audio positions already save; this adds the visible part.
- [ ] **#14 End-user trust check.** A **separate program** (`thc-inspect`, shipped as its own .exe, macOS binary and AppImage) that inspects how THC works: what it writes, what it stores, and whether it makes network connections. Read-only. Doubles as the "no network" test from #2.
- [ ] **#18 Always-on-top for MPV.** Owner delegated the design. Plan: feasibility test on Windows, macOS, X11 and Wayland; setting is Off / While playing / Always; ship it where it works, with a clear note on Wayland.

## Rules for every item
- Private and local: no network calls, no telemetry, no accounts.
- Never write to, move, or rename media files.
- Works on Windows, Linux (Wayland and X11) and macOS.
- Keyboard accessible, with scalable text and high contrast.
- Tests with each change; CI stays green on all three OSes.

## Done means
- Every planned item is shipped, or explicitly moved to a later release in this file.
- `ctest` and CI pass on all three OSes.
- Packages are rebuilt as 0.2.0 and the changelog lists each change with its issue number.

## Order of work
1. #1 queue (the others build on it).
2. #7 search and #11 listening history.
3. #14 trust check.
4. #18 feasibility, then ship only where it works.

## Queue decisions (settled)
- A video that comes up in the music queue opens in a **new MPV window**. (The video queue itself uses one window for its whole run.) Per-item "listen only" and "skip" stay available as overrides.
- When a queue ends, playback **stops, unless the queue is chained**. **Queue chaining:** a portal's queue can be chained to play after another's (for example video then music). A chain runs once per start, so two queues chained to each other cannot loop forever.
- Starting a video **pauses the music**. A setting turns this off, and another controls whether music resumes after the video.
