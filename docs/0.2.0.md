# 0.2.0: release plan

**Status:** proposed. Current version is 0.1.3. Per the versioning rules, a minor release holds big new features: the queue (#1) is the headline, with the smaller music and privacy items alongside it.

## Goal
Add a real queue for audio and video, make music easier to find and keep track of, and give users a way to check that THC really is private and offline.

## Planned
- [ ] **#1 Comprehensive queue (headline).** THC-managed queue; two queues (music and audiobooks, and video) that are separate but interchangeable: any item can go in either queue, and the player picks the right backend per item. Videos play in one MPV window; songs and audiobooks stay inside THC's own player. Session only; optional export and import as M3U8; reorder, skip, shuffle and repeat; keyboard accessible. See the issue and its export comment for the full spec.
- [ ] **#7 Search in the music portal.** Search as you type, local only, using the audio tags from 0.1.1. The user chooses what to search (all, artists, albums or songs). Light typo tolerance is always on, with no toggle. **Audiobooks are never part of music search** and there is no option to add them.
- [ ] **#11 Listening history.** Stored in the history database (a play event per listen). A play counts at **65%** of a track by default, changeable in Settings. History saving can be turned off **separately for each portal** (Video, Music, Audiobooks). Played items from the queue are recorded. A "Recently played" and "Continue listening" view, play counts, last played, mark played or unplayed, and a way to pause history. Audio positions already save; this adds the visible part.
- [ ] **#14 End-user trust check.** A **separate program** (`thc-inspect`, shipped as its own .exe, macOS binary and AppImage) that inspects how THC works: what it writes, what it stores, and whether it makes network connections. Read-only. Doubles as the "no network" test from #2.
- [ ] **Media keys and now-playing integration (new issue to file).** Hardware media keys and the system "now playing" controls, driven by whichever queue is active. Linux: MPRIS over the local D-Bus. Windows: the System Media Transport Controls (plus media-key hotkeys). macOS: the Now Playing center and remote commands. Privacy-aware: titles and covers shared with the system are controlled per portal, and video titles are off by default.
- [ ] **#18 Always-on-top for MPV.** Owner delegated the design. Plan: feasibility test on Windows, macOS, X11 and Wayland; setting is Off / While playing / Always; ship it where it works, with a clear note on Wayland.

## Housekeeping

## Options reference (settings per feature)

**Queue**
- Auto-advance video; next-episode countdown (off by default); repeat (off / one / all); shuffle.
- Previous button: restart after 3 s, or always go back.
- Resume saved positions for queued videos, songs and audiobooks (per type).
- Add a season or show: all episodes, or unwatched only.
- "Add to queue" sends to the item's home queue, or the active queue.
- **Backlog:** played items stay in the queue above the current one (greyed), like most music players, so Previous walks back through them. The backlog lasts for the session.
- **Add** puts items at the **end** by default. **Right-click** opens a fuller menu: Play now, Play next, Add to end, Add to the other queue, Play from here, Add unwatched only (for shows), Remove, Move to the other queue, Go to album or show, Mark played or unplayed.
- A **confirmation window** before clearing a queue.
- Chaining: per queue, "after this ends, play: nothing / the other queue".
- Video in the music queue: new MPV window (default), listen only, or skip, per item.
- Pause music when a video starts (on by default); resume music after the video.
- Export paths relative or absolute; queue panel and reorder hotkeys are remappable.

**Music search**
- What to search: all, artists, albums or songs. Default is **all, every time**; a setting "Remember my search scope" (off by default) keeps the last choice.
- Light typo tolerance always on; audiobooks never included.
- Results per group; clear search when leaving; search hotkey.

**Listening history**
- History on or off per portal (Video, Music, Audiobooks).
- "Counts as played" percentage (default 65%).
- Resume only audio longer than N minutes.
- History is **kept forever** (no expiry setting).
- Turn off saving new history, or **clear** it, each behind a **confirmation window**; remove a single item; export as JSON or CSV.
- Private session: record nothing until THC restarts.

**Privacy tool (`thc-inspect`)**
- Output as readable text or JSON; verbosity level.
- Point it at any THC data folder; exit code reflects pass or fail, so it can run in CI.
- Read-only always; never connects to the network itself.

**Media keys and now playing**
- Media keys: off / only when THC is focused / **global (default)**. THC only claims the keys while it has something loaded, so other players keep them otherwise.
- Share now-playing info with the system, per portal: music **on**, audiobooks **on**, video **off** (the system just sees "THC"), so what you watch isn't shown on lock screens or overlays.
- Share cover art with the system: on for music and audiobooks.
- Titles shared: full, or "Playing" only.
- Next and previous act on the active queue; Previous restarts the item after 3 s, as in the queue.
- Seek keys: 10 s for music and video, the audiobook skip length (30 s) for audiobooks.
- **Stop key pauses** (it never clears the queue).

**Always-on-top**
- Off / while playing / always; macOS window level; ignore in fullscreen; toggle hotkey.

## Rules for every item
- Private and local: no network calls, no telemetry, no accounts.
- Never write to, move, or rename media files.
- Works on Windows, Linux (Wayland and X11) and macOS.
- Keyboard accessible, with scalable text and high contrast.
- Tests with each change; CI stays green on all three OSes.

## Done means
- Every planned item is shipped, or explicitly moved to a later release in this file.
- `ctest` and CI pass on all three OSes.
- Packages are rebuilt as 0.2.0 and the changelog lists each change with its issue number.

## Queue decisions (settled)
- A video that comes up in the music queue opens in a **new MPV window**. (The video queue itself uses one window for its whole run.) Per-item "listen only" and "skip" stay available as overrides.
- When a queue ends, playback **stops, unless the queue is chained**. **Queue chaining:** a portal's queue can be chained to play after another's (for example video then music). A chain runs once per start, so two queues chained to each other cannot loop forever.
- Starting a video **pauses the music**. A setting turns this off, and another controls whether music resumes after the video.
