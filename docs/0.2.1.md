# THC 0.2.1: build spec

**Status:** ready to build, **after 0.2.0 ships** (it touches code the queue uses). Current version: 0.1.3 (0.2.0 in progress). This is a patch release: bug fixes, one small feature, and a performance baseline. No big new features.

## How to work on this (read first)
- Work on `dev`; never push to `main`. Commit and push after each slice (see "Build order").
- **Deliver 0.2.1 efficiently.** Build what this file says.
- **If you find a bug, a missing piece, an idea, or anything out of scope: file a new GitHub issue and move on.** Do not stop to fix it, and do not widen a slice. Only fix it now if it blocks the slice you are on, and say so in the commit.
- Each fix gets a test that fails before the fix and passes after.
- Keep `README.md`, `CHANGELOG.md` and this file true as you go. If you deviate from this spec, write the deviation here and say why.
- The hard rules in `AGENTS.md` still apply (no network, never write to media files, C only, three operating systems, history compatibility).

- Private and local: no network calls, no telemetry, no accounts.
- Never write to, move, or rename media files.
- Works on Windows, Linux (Wayland and X11) and macOS.

- Logic that does not need SDL goes in `thc_core` and is tested there.
- Confirmation windows are real modal dialogs.

## 1. #24: history must not re-key another file's entry

**Problem:** `find_moved()` in `src/history.c` re-keys a row with the same size and a different path when exactly one such row exists and the duration is unknown. If the old file still exists, saving the new file steals the old file's row.

**Fix:**
- A row counts as "moved" only if its **old path no longer exists in the library**.
- History cannot check that itself, so add `history_set_exists_check(History *h, bool (*exists)(void *ud, const char *rel_path), void *ud)`. The app passes a check that looks the relative path up in **every** library root (video, music, audiobooks, sections).
- **Safe default:** with no check set, or when the check cannot decide, **do not re-key**. A moved file then starts a fresh entry instead of a wrong one.
- No schema change (see the History compatibility rule: nothing to migrate).

**Files:** `include/history.h`, `src/history.c`, `src/main.c` (install the check after each scan; keep it valid while the library is being replaced), `tests/test_history.c`, `tests/test_history_compat.c`.

**Tests:**
- Two files with the same size, both played: both keep their own rows (the 0.2.0 album case).
- A real move (old path gone from the library) keeps its history.
- A rename when the old path still exists elsewhere does not steal the row.
- No check installed: nothing is re-keyed.
- Existing compat tests still pass.

## 2. #20: album order with untagged files

**Problem:** `music_tracks()` in `src/music.c` sorts by disc and track only if **every** file has a track number. One untagged or corrupt file puts the whole album in file-name order, and the shown numbers (from tags) no longer match the order.

**Fix:**
- Tagged tracks sort by **disc, then track**. Files **without** a track number follow, in file-name order. All untagged: file-name order (unchanged).
- Move the ordering into `thc_core` as a function over an array of `TagInfo *` (some may be NULL) that returns the sort order, so it can be tested without SDL. `music_tracks()` calls it.
- **One order everywhere:** the album track list, the playback queue, and "Play" all use it.
- **Displayed numbers:** tagged tracks show their tag number; untagged tracks show "–" instead of a made-up number, so the numbers never disagree with the order.

**Files:** `include/tags.h`, `src/tags.c`, `src/music.c`, `src/portal_music.c`, `tests/test_tags.c`.

**Tests:** mixed tagged and untagged (tagged first by track, then untagged by name); all untagged (file-name order); duplicate track numbers (stable); multi-disc; NULL tag entries; the issue's exact folder (tracks 3, 2, 1, 4 plus untagged and corrupt files gives 1, 2, 3, 4, then the rest).

## 3. #22: thumbnail keys must not collide

**Problem:** `thumb_key()` hashes only size and mtime, so batch-copied files share one thumbnail.

**Fix:**
- Key = hash of **size + mtime + the first 4 KB + the last 4 KB** of the file. Renames and moves still keep the thumbnail; different files no longer collide.
- **Read the file once per session, not every frame.** Compute the key when a file is first asked for and remember it (by path) for the session. Reading is read-only.
- Old cache entries just regenerate; the existing 500 MB prune clears the old ones.
- Unreadable files: fall back to the old key, no crash.

**Files:** `include/thumbs.h`, `src/thumbkey.c`, `src/thumbs.c`, `tests/test_thumbs.c`.

**Tests:** same size and mtime but different content gives different keys; same content renamed or moved gives the same key; files shorter than 8 KB; unreadable file; the key is computed once per file per session (count reads); media file unchanged.

## 4. #21: large cover images must not blow up memory

**Problem:** `src/art.c` decodes a cover at full size before scaling. A 7000×7000 JPEG (676 KB on disk) takes peak memory from about 180 MB to about 500 MB. The same applies to folder images and thumbnail sidecar images.

**Fix:**
- Before decoding, read the image **dimensions** (`stbi_info_from_memory`). If it is above a pixel limit (**24 megapixels**, one constant), **skip it**: show the generated placeholder and log once.
- Apply the same check to embedded covers (`tag:` paths), folder images and sidecar thumbnails.
- Decode one image at a time and free the full-size pixels as soon as the downscaled texture exists.
- Cap embedded art read size (already bounded by the tag reader; confirm).

**Files:** `src/art.c`, a small testable size-check helper, `tests/` fixture `huge.jpg` (7000×7000, flat colour, under 1 MB), `tests/CMakeLists.txt`.

**Tests:** the helper rejects the 7000×7000 image and accepts a normal cover; a corrupt header is rejected without crashing; **peak memory** loading the huge image stays under a set limit (measure with the OS's peak-RSS counter where available, skip on Windows); a normal cover still loads.

## 5. #25: MPV screenshots go to THC's folder and show up in THC

### Behavior
- Pressing MPV's screenshot key (`s`) saves to **`<THC data folder>/screenshots/`**, never to a media folder or the working directory.
- THC sets MPV's `screenshot-directory` after startup (as a property, since `mpv.conf` overrides earlier options), like its other controlled options.
- New **Screenshots** section in the **Video** portal: a grid of the saved images, newest first, with the video title and time from the file name. Selecting one opens it larger.
- Per image: open in the file manager, copy path, **delete** (confirmation window).
- Empty state explains where screenshots go and how to take one.
- Screenshots are what you watched, so they stay local and appear in `thc-inspect`'s file list.

### Settings
| Key | Type | Default |
| --- | --- | --- |
| `screenshot_dir` | path | empty = `<data>/screenshots` |
| `screenshot_format` | png / jpg / webp | png |
| `screenshot_template` | MPV template | `%{media-title}-%P` |

- THC controls these three MPV options (`screenshot-directory`, `screenshot-format`, `screenshot-template`); the config check marks them as THC-controlled and `mpv.conf` values for them are ignored.
- The folder is created if missing; if it cannot be written, THC says so instead of failing silently.

### Files
`src/video.c`, `src/main.c`, `src/portal_video.c` (Screenshots section), `src/art.c` (images load through the existing cache, with the #21 size limit), `src/screen_settings.c`, `src/settings.c`, `src/mpvconf.c`, `README.md`.

### Tests
MPV is started with the right directory, format and template (also when `mpv.conf` sets different values); the folder is created; the gallery lists files newest first and ignores non-images; delete removes only files inside the screenshots folder (path check); a custom folder works; nothing is written into the media folder.

## 6. #12: performance baseline

**Goal:** know how fast and how big THC is before 0.3, without optimizing yet.

- Add `tools/perf/`: a script that builds a **synthetic library** (for example 1,000 / 10,000 / 50,000 files, with tags and a few covers) in a temp folder, and a way to run THC headless against it.
- Record, per size: **scan time, tag-read time, peak memory, time to first frame, frame time while scrolling, search latency per keystroke (once 0.2.0 search exists), queue operations with large queues.**
- Write results and **targets** to `docs/performance.md`.
- **Do not optimize in this release** except trivial one-line wins. For anything slow or large, **file an issue** with the numbers.
- An optional manual or nightly CI job runs the 1,000-file case.

**Done when:** `docs/performance.md` has a table of measured numbers on at least Linux, the script is committed and documented, and any problems found are filed as issues.

## 7. #6: accessibility shaders (optional)

Only if time allows; otherwise file a follow-up and say so in the changelog.

- Ship a small pack of **THC-written GLSL shaders** (Unlicense) in `shaders/` of the install, off by default: **color-blindness correction** (protanopia, deuteranopia, tritanopia), **contrast boost**, **dark-scene lift**, **grayscale**. A **flash limiter** is a feasibility question (it needs the previous frame); if it cannot be done safely, file an issue and leave it out.
- The existing Shaders list in Settings → MPV gets a **toggle per shader**, order control, a "reset to none" button, a plain-language description, and an intensity slider where it makes sense.
- Toggling writes to THC's own `mpv.conf` `glsl-shaders` line (the same file power users edit) and a **remappable hotkey** toggles the accessibility set at runtime.
- A broken shader must not black-screen playback: validate on load, fall back to none, and show the shader name and error.
- Applies to the video output only, never to THC's own interface.

**Tests:** enable, disable and reorder write the right `glsl-shaders` value; reset clears it; a broken shader falls back safely; shaders are read only from THC's folder.
